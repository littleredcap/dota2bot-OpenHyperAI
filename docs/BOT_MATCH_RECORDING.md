# Bot 对局记录规范

**每场都记录**，包括获胜、失败、中断、设置错误和未生成录像。开局前抓取版本；对局结束后，在下一局开打或交接前补齐仓库里的单局报告和 [对局索引](BOT_MATCH_INDEX.md)。先记录已核实事实，缺失项写“待核对”或“不可观测”，不要用上局数据代填。

## 开局前

1. 记录本地日期时间（含时区）、客户端补丁及可获取的构建号。分别记录 OHA 与对手脚本的名称、版本/工坊 ID 或本地脚本哈希。无独立版本号时明确写明；不要把脚本版本等同于客户端补丁。
2. 记录**实际加载**的代码分支、完整 Git SHA 和工作区状态。校验脚本联接/同步目标。记录本地配置、临时阵容覆盖文件的哈希和可重放配置。跟踪未提交的代码改动时，保存可重放的差异，不记录密码、账号或其他不必要的个人数据。
3. 选定上一场可比局以及一个已核实的较好对照局。记录从对照 SHA 到本局 SHA 的行为改动，列出需要验证的现象。固定对手、难度、地图、阵容和速度；同时记录实际分路、侧别和任何偏差。

## 结束后

1. 在 `docs/BOT_MATCH_REGRESSION_<比赛ID>.md` 写报告；无 ID 时用 `docs/BOT_MATCH_REGRESSION_<日期时间与短SHA>.md` 并标记缺档，取得 ID 后更新，不重复记一局。索引注明完成、提前中止或缺档。只有确认基地摧毁或经过核实的结算胜负才计入胜率。主观判断“已经输了”不得替换结算。
2. 时间统一用游戏钟。至少记录结果、时长、击杀、塔和兵营；5/10 分钟记录队伍净资产差、补刀、反补以及本轮受关注英雄；12–25 分钟记录首次关键攻防、到场、清兵、符文和目标收益，20 分钟记录净资产差与塔伤。能获取时补充 GPM/XPM、收入来源与关键技能。明确方向、取样口径和数据来源。以上指标是录像统计，不是 MAX+ 官方评分。
   对线专项按[英雄贡献评估](BOT_HERO_CONTRIBUTION_METRICS.md)做五分钟分段，对比同一职责的机会、收益和代价，再定位需要复盘的片段。
3. 逐项写出关键时间、可见证据、结果及待验证原因。拉野至少区分“下达动作、野怪跟随、实际卷入友军兵、后续一至两波交汇变化”，缺少一环就明确写出。区分攻防失败于未到场、到场不敢进入、没有清线、站位或技能配合。避开凭单局胜负归因。
4. 写下一轮的可验证指标，说明是否仍需同版本重复、用较好版本作 A/B，或先补日志。文档提交与行为提交分开；不自动回退或改变主线，不提交大体积录像。

## 单局模板

- 对局 ID / 录像来源、开始时间、完成状态：
- 客户端补丁 / 构建；OHA 脚本版本；对手脚本版本：
- 分支 / 完整 SHA / 工作区 / 实际加载位置和配置校验：
- 条件（难度、阵容与分路、速度、资源规则、异常）：
- 对照局及本次改动（行为提交）：
- 时长、胜负、击杀、塔、兵营：
- 5 / 10 / 20 分钟统计、经济来源及受关注英雄：
- 关键时间线、已验证问题、待验证原因：
- 下一轮测试指标和未采到的数据：
