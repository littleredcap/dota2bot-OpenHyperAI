# 战后团队分工：先保住回防路径，再分配推进和收线

相关录像：[9107324797](BOT_MATCH_REGRESSION_9107324797.md)，[16 项决策审计](BOT_DECISION_AUDIT_9107324797.md)。37:25 敌方三人同时处于阵亡状态，随后我方离开高地区域，38:14 / 38:17 又失去龙骑和骷髅王。本轮用这个窗口检验通用规则，不绑定英雄、阵容、对手或时间戳，不修改早梅肯与公平模式设定。

## 本轮实现

- **单一决策接口**：当前切片在中三塔已倒时生效，目标为仍存在的中路兵营，若兵营全倒则覆盖基地。用可见或已目击的推进、现有公开死亡状态估算、兵线抵达、可见开战危险估计最早压力。看不清时有保守上限；不是从战争迷雾读取精确复活、冷却或敌人方位。
- **时间窗与角色**：根据实际位置/移动速度、清线能力与可用时间、血量、可观察的路径威胁，选一名清线者；时间紧或已经有敌方集结迹象时再选一名支援。排序有固定 ID 作为同分条件。保留已在位且有效的现任清线员；一名更强却尚未到位的候选不能抢走这个席位。不把排队或正在引导的 TP 当作已到位；回防 TP 只在有安全建筑落点、能比走路更早到时选择。
- **行动约束**：守塔使用这份分工，推进在选目标和已经进入模式后的两处复核，刷钱筛选路线并在发移动/攻击命令前复核，外出收钱或推进的 TP 同样要通过约束。还未形成有效掩护时，只允许留在附近或算得过来的往返行动；外出的 TP 当作本次已消耗，不再算作立即可用的返程。形成掩护后，非留守队友可以正常收线、推进。既有正在接战、基地紧急回防和高地救援仍有独立优先通道。
- **可观测性**：可选 `TracePostFightCoverage` 记录角色变动、是否已到位以及时间预算分段，默认关闭；目前不是全队所有模式的完整追踪。各 Bot 通过同一计算和稳定候选顺序得到分工，没有引入跨 Bot 强一致服务器；实战要确认不同 Bot 的观测延迟不会造成临时漏岗。

## 回归与后续

- 断言压力来时选清线和可走回的支援；距离过远或 TP 未落地时不能把另一个人一起派走；迟到的候选不能替换在位的人；真正接班后重新放行其他队友。不安全时不能派人去强站。测试目标是同一个规则对变化做出相反动作，不是硬编码 37:25。
- 下一块建议把覆盖需求抽到每条防线：输入用兵线 ETA、目标价值、已有守将、敌方可见压力与其他目标价值，先合并中一/二塔、上下路，再接团战/经济。不要把各模式的局部阈值继续叠加成第二套全局决策。
- 本次按要求不打开或操控客户端，不新开对局；完整逻辑只算离线验证。
